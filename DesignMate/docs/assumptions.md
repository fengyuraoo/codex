# Assumptions

- v0.1 先使用命令行和本地文件完成，不开发完整桌面软件。
- v0.1 不接入复杂 AI API，只保留提示词模板和后续接口空间。
- 用户会把资料手动放入 `data/inbox/` 或 `data/library/`。
- 文件名会包含一定语义，例如“草图”“调研”“反馈”等关键词。
- 图片、PDF、DOCX、PPTX 暂不解析正文，仅记录元信息。
- 作品集项目的具体成果、调研结论、模型细节均需用户后续补充。
- 当前示例资料只用于测试，不代表用户真实项目成果。
- v0.3 假设 SQLite FTS5 在当前 Python 环境中可用；如果不可用，系统使用 fallback 搜索。
- v0.3 Web UI 采用静态文件模式，适合直接打开和演示；API 服务作为可选本地服务单独启动。
- 示例数据集为测试检索质量而创建，不代表用户真实调研结论。
- v0.4 假设用户在需要保存编辑时会启动本地 API；只打开静态 HTML 时不会写入 SQLite。
- v0.4 将人工编辑后的资料标记为 `confirmed`，后续自动分类不会覆盖 confirmed 资料。
## v0.5 假设

- 今日新增资料暂时不做历史快照对比，先用 `data/inbox` 文件数量、`data/library` 文件数量、上次扫描时间和上次报告生成时间提示导入状态。
- 批量编辑默认替换 tags，而不是追加 tags；下一轮需增加“追加/替换”模式。
- 作品集页面草稿先采用规则版生成器，不调用外部 AI API，避免影响本地优先和隐私边界。
- `drafts/portfolio_page_draft.md` 作为最近一次草稿输出，同时保留项目专属草稿文件，减少覆盖带来的误解。
