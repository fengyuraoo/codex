# DesignMate v0.7.5 Real File Upload & Scan Integration

## 1. 本轮目标

v0.7.5 将 Add Materials 里的 Upload Files 从占位入口升级为真实可用的本地文件上传功能。用户可以在网页中选择或拖入设计资料，DesignMate 会把文件保存到本地资料目录，解析元信息或正文，并写入 SQLite，让资料可以被 Search 和 Ask DesignMate 使用。

## 2. 为什么真实文件上传是 Add Materials 的关键

Add Materials 是 DesignMate 工作流的入口。如果用户仍然需要手动打开文件夹、复制文件、再运行脚本，网页体验会断开。真实上传让“添加资料 -> 搜索资料 -> 询问 DesignMate”的路径变得连续，更接近一个可用的本地设计资料工具。

## 3. 支持的文件类型

- `.png`
- `.jpg`
- `.jpeg`
- `.webp`
- `.gif`
- `.pdf`
- `.docx`
- `.pptx`
- `.txt`
- `.md`
- `.csv`
- `.xlsx`

不支持的文件类型会返回友好错误，不会写入资料库。

## 4. 上传后如何进入本地资料库

上传 API 为 `POST /api/upload-materials`，使用 `multipart/form-data`。文件会保存到：

`DesignMate/data/uploads/`

后端会对文件名做安全处理，阻止路径穿越，并在重名时自动生成唯一文件名，避免覆盖已有资料。保存后会复用现有 `material_parser`、`classifier` 和 `database` 流程，把资料写入 SQLite，并重建本地搜索索引。

## 5. 上传后如何用于 Search 和 Ask

- Markdown / TXT / CSV 会尽量读取正文并写入全文索引。
- PDF / DOCX / PPTX 会复用现有可选解析能力；如果环境缺少依赖，则至少记录文件元信息、路径和用户备注。
- 图片会记录文件名、路径、类型和尺寸元信息；视觉理解仍未接入。
- 用户填写的 project、design_stage、use_case 和 user_note 会写入 material 记录，用于搜索排序和 Ask DesignMate 的上下文。

## 6. 当前限制

- 图片仍未接真实视觉理解。
- PDF / DOCX / PPTX 深度解析仍可继续增强。
- 真实 AI provider 仍未接入。
- Electron 桌面端仍未完成。

## 7. 验收方式

1. 启动 API：`python DesignMate/scripts/start_api.py`
2. 启动前端：`python DesignMate/scripts/start_frontend.py`
3. 打开 `http://127.0.0.1:8766/`
4. 进入 Add Materials，选择或拖入 `.md` / `.txt` / 图片等资料。
5. 填写 project、design stage、use case、user note。
6. 点击 Upload to Library / 上传并加入资料库。
7. 回到 Text Search，搜索文件名或内容关键词。
8. 进入 Ask DesignMate，询问这条资料可以用于什么设计场景。
